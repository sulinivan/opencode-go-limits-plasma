# OpenCode Go Limits — виджет для KDE Plasma

Показывает лимиты **OpenCode Go** (5 часов / неделя / месяц) прямо на панели
KDE Plasma или на рабочем столе — без браузера и без root.

Это переписывание [Windows-виджета](https://github.com/Souzn1k3/opencode-go-limits)
на нативный стек Plasma 6 (QML). Поведение, пороги и тексты сохранены,
платформенные особенности (автозапуск, «поверх всех окон», позиция окна)
заменены штатными механизмами KDE.

## Возможности

- Три полосы: **5 часов**, **неделя**, **месяц** — процент, полоса и обратный отсчёт до сброса.
- Цвет по порогам: зелёный `< 60%`, жёлтый `60–85%`, красный `≥ 85%` (цвета берутся из темы Plasma).
- Обновление раз в N минут (по умолчанию 5) + кнопка ручного обновления.
- Все экземпляры виджета (панель + рабочий стол) показывают одни и те же данные:
  обновление, нажатое в одном месте, появляется везде за ~3 секунды.
- Уведомление KDE, когда 5-часовой лимит превышает порог (по умолчанию 85%) —
  ровно одно на все экземпляры за окно сброса.
- На панели — компактный индикатор с процентом, на рабочем столе — полная версия.
- Настройки через штатный диалог Plasma.

## Требования

- KDE Plasma 6 (проверено на 6.6.4)
- `python3` (только стандартная библиотека, никаких pip-пакетов)
- `tail` из coreutils (есть в любой системе; используется для чтения общего журнала)
- Авторизованный `opencode`: ключ `opencode-go` должен лежать в
  `~/.local/share/opencode/auth.json` (вход выполняется командой `opencode auth login`)

## Установка (без root)

```bash
./install.sh
```

Скрипт кладёт пакет в `~/.local/share/plasma/plasmoids/org.opencode.limits/`
и файл уведомлений в `~/.local/share/knotifications6/`.

Затем добавьте виджет:

- **на панель**: правый клик по панели → «Добавить виджеты» → *OpenCode Go Limits*;
- **на рабочий стол**: правый клик по рабочему столу → «Добавить виджеты» → *OpenCode Go Limits*.

Удаление:

```bash
./uninstall.sh
```

## Как это работает

```
любой экземпляр ──раз в N минут──> backend.py ──HTTPS──> opencode.ai/zen/go/v1/usage
                                        │
                                        ├─ читает auth.json
                                        ├─ пишет строку JSON в общий журнал usage.log
                                        └─ решает, кому слать уведомление (--threshold)

все экземпляры ──раз в 3 с──> tail -n 1 usage.log ──> рисуют полосы и отсчёт
```

Общий журнал — это и есть синхронизация: ответ любого экземпляра попадает в
`usage.log`, а остальные читают оттуда последнюю строку. Поэтому кнопка
«Обновить» и отсчёт до сброса одинаковы во всех виджетах. Запрос делает тот
экземпляр, у которого сработал таймер (у каждого свой интервал).

- `package/contents/ui/main.qml` — виджет: таймеры, вызов backend, чтение журнала, уведомления.
- `package/contents/code/backend.py` — ключ, сеть, нормализация ответа, журнал, уведомления, тексты ошибок.
- `package/contents/code/logic.js` — чистая логика: пороги цвета, отсчёт, тексты, разбор JSON.
- `package/contents/ui/UsageBar.qml` — одна полоса прогресса.
- `package/contents/ui/configGeneral.qml` + `contents/config/main.xml` — настройки.
- `package/contents/notifications/opencode-limits.notifyrc` — событие для KNotification.

Рабочие файлы (журнал `usage.log` и метка `notified`) создаются рядом с `backend.py`
внутри каталога пакета и удаляются вместе с ним при `./uninstall.sh`.

### Что не перенесено из Windows-версии и почему

| Windows | Plasma | Причина |
|---|---|---|
| `autostart` (реестр Run) | — | виджет существует вместе с сессией Plasma, запускать нечего |
| `topMost`, «без рамки» | — | порядок окон и оформление задаёт панель/рабочий стол |
| Сохранение координат окна | — | Plasma сама хранит позицию виджета |

## Настройки

Правый клик по виджету → «Настроить OpenCode Go Limits», либо кнопка с шестерёнкой
в полной версии.

- **Интервал обновления (мин)** — 1…120.
- **Уведомлять о 5-часовом лимите** — вкл/выкл.
- **Порог, %** — 50…100.

## Проверка работоспособности

Быстрая проверка без виджета — видно, что ключ найден и сервис отвечает:

```bash
python3 package/contents/code/backend.py --test
```

## Разработка

```bash
python3 tests/test_backend.py     # нормализация, тексты ошибок, ключ, журнал, уведомления
node tests/logic.test.js          # цвет/отсчёт/тексты, разбор JSON
./bench/measure.sh 30             # RSS и CPU plasmashell
```

Проверить, что синхронизация жива: запустите `backend.py` вручную — его строка
попадёт в общий журнал, и все виджеты обновятся в течение ~3 секунд.

```bash
python3 package/contents/code/backend.py
```

**Важно при правках QML:** уже запущенный апплет держит старый код в памяти.
После `./install.sh` перезапустите plasmashell (или удалите и добавьте виджет
заново, но при обновлении файлов надёжнее перезапуск):

```bash
plasmashell --replace &
```

## Диагностика

| Симптом | Что делать |
|---|---|
| `ошибка: ключ отклонён (401) — проверьте auth.json` | ключ недействителен: `opencode auth login` |
| `ошибка: сервис лимитов недоступен (404)` | изменился API, нужно обновить `backend.py` |
| `ошибка: Нужна подписка OpenCode Go: ключ opencode-go не найден` | в `auth.json` нет записи `opencode-go` |
| `ошибка: backend.py не ответил вовремя` | нет сети или запрос длится дольше 30 с |
| Виджет есть, но показывает «—» | запустите `backend.py --test` и посмотрите текст ошибки |
| Второй виджет не обновляется | проверьте, что оба виджета одной версии: `kpackagetool6 --type Plasma/Applet --list` |
| После правок виджета ничего не изменилось | перезапустите plasmashell: `plasmashell --replace &` |

## Производительность

Прямое сравнение «до/после» невозможно: оригинал работает только на Windows.
Ниже — разбор по ресурсам и реальные замеры новой версии.

**Что изменено по сравнению с оригиналом:**

| Область | Windows-версия | Plasma-версия |
|---|---|---|
| Процессы | exe-лаунчер → скрытый `powershell.exe` → WinForms | всё внутри `plasmashell`, 0 постоянных процессов |
| Старт | распаковка скрипта на диск + загрузка .NET/WinForms | ничего не распаковывается |
| Периодичность | таймер 5 мин (сеть) + таймер 30 с (перерисовка ~12 контролов) | таймер 5 мин (сеть) + опрос журнала раз в 3 с + пересчёт отсчёта раз в 30 с |
| Синхронизация виджетов | нет (у каждого экземпляра своё состояние) | общий журнал: обновление в одном месте видят все |
| Разбор данных | `ConvertFrom-Json` → дерево PSObject на каждое поле | один `JSON.parse` |
| Отрисовка | пересоздание/перерисовка контролов WinForms | прямоугольники в сцене Qt, меняется только ширина |
| Повторный запуск | мьютекс + `FindWindow` | не требуется (экземпляр один на контейнер) |
| Хранение настроек | свой `config.json` + ручная запись | штатный конфиг Plasma |
| Смена ключа | требовался перезапуск (ключ кэшировался) | подхватывается на следующем обновлении |

Сетевой запрос не блокирует интерфейс: `backend.py` запускается асинхронно через
движок `executable`. Опрос журнала — короткоживущий `tail -n 1` (единицы
миллисекунд), постоянных процессов виджет не создаёт.

**Замеры (этот ПК, Plasma 6.6.4, X11):**

```
backend.py (ключ + HTTPS + JSON):       ~0.60 с на вызов (раз в 5 минут)
RSS plasmashell без виджетов:            310 680 kB
RSS plasmashell с двумя виджетами:       311 412 kB   (+0.7 MB на два, ≈0.4 MB на экземпляр)
CPU plasmashell (45 с):                  0.067% без виджетов / 0.089% с виджетами
```

Методика: виджеты убирались и добавлялись через Plasma Scripting API, RSS брался из
`/proc/<pid>/status`, CPU — из `utime+stime` за 45 секунд. Разница в CPU (+0.02%)
сопоставима с собственными колебаниями plasmashell и включает опрос журнала
(2 экземпляра × 15 запусков `tail` за 45 с). Дополнительно ~21 MB разово уходит на
загрузку QML-модулей (plasma5support, KNotification) при первом создании виджета —
в замере выше они уже были загружены, поэтому видна только разница по экземплярам.
Обновление данных — один процесс `python3` на 0.6 с раз в 5 минут.
